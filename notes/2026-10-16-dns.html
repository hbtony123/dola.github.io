2026-10-16 · 上线实录 ② / ④ · 域名解析

顶点上的
那条 CNAME

站点上线之后轮到邮箱。我以为加两条 MX 记录就完事，结果卡在一条早就存在的 CNAME 上。

邮箱要能收信，得在 DNS 里放 MX 记录。而 dola.cn 的顶点（也就是 @ 本身） 当时挂着一条 CNAME——指向 GitHub Pages。加 MX 的时候，控制台直接报记录冲突。

先把顶点腾出来

知识点｜CNAME 是独占记录
同一个名字下，CNAME 不能和 A、MX、TXT 共存——这是 DNS 规范，不是哪家服务商的偏好。 所以顶点要收信，就得先把 CNAME 换成 A 记录。

顺带一提，GitHub Pages 官方对顶点域名的要求本来也是 4 条 A 记录 （185.199.108.153 那四条）。换过去之后，站点照常跑，顶点也空了出来。

然后邮箱的记录一条条加进去：MX 三条、SPF 一条。

通配符在偷偷吃掉 DKIM

第二个坑更隐蔽。之前为了「任何子域名都能打开这个站」，我们配了一条通配符 * 的 CNAME。 结果一查 mail._domainkey.dola.cn——DKIM 签名该待的地方——返回的是 GitHub Pages 的地址。

原因：通配符会接管所有没有显式记录的名字，包括 mail._domainkey 和 _dmarc。也就是说，只要它在，DKIM 永远配不上——而且不会报任何错， 只是你发出去的邮件更容易被判成垃圾。

删掉通配符，这两个名字空了出来，MX 和 SPF 原样都在，站点毫发无伤。

别信中间任何一层缓存

排查过程中有一步差点把我带偏：我从公共 DNS 查询，明明已经删掉的 CNAME 还在返回。 一度以为没保存成功。其实那是缓存——TTL 十分钟，十分钟后自然就消失了。

知识点｜改完 DNS 怎么验证
直接问权威服务器（比如域名的 NS 机器），看返回的记录是不是你写的那几条； 再换一个公共 DNS 复核一遍。两次都对，才算真的生效。
