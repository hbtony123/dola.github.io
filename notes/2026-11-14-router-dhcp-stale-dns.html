退役的电脑还在发 DNS：路由器 DHCP 里的死地址

设备退役不只是关电源。它还可能在路由器的 DHCP 配置里继续上班，拖慢全网每一台设备。

查网速时发现系统解析器列表里有两个 DNS：一个是本机地址，一个是 192.168.0.201。 后者是已经退役下线的旧电脑的地址。ping 它，100% 丢包；dig 它，三秒超时。 但每个新联网的设备都还在拿它当备用 DNS。

一、死地址从哪来：DHCP 租约

ipconfig getpacket en0 会显示路由器 DHCP 实际下发的配置： domain_name_server: {192.168.0.103, 192.168.0.201}。 也就是说这不是哪台电脑自己配的，是路由器发的。

原因不难猜：旧电脑曾经在本机跑 DNS 服务（广告过滤之类），当时在路由器 DHCP 里把它设成了备用 DNS。 后来电脑退役关机，路由器的配置没人改，这个死地址就一直发下去。 Mac 收到它会把它放进系统解析兜底链，Windows 收到它也有同样的表现。

二、症状：不止慢，还可能直接上不了网

备用 DNS 的坏处不在平时。主 DNS 能答的时候你感觉不到它；一旦主 DNS 停止服务 （比如这次把本机 AdGuard 停掉），所有设备只能去问那个死地址， 表现就是网页完全打不开、nslookup 连续超时——Windows 上尤其明显，因为它的解析器不像 macOS 那样会并行询问多个服务器。

排查时 ping 是通的、TCP 能连、IP 直连也正常，唯独域名解析全挂。 这种"网络能通但域名全解不出来"的组合，先查 DNS 服务器地址，别急着怀疑网线或者运营商。

三、修复：改路由器，然后以续租为验收

修复只改一处：路由器 DHCP 服务器设置里的首选/备用 DNS，改成公共 DNS（223.5.5.5 和 119.29.29.29）。 已故设备相关的地址全部删除，本机 AdGuard 停用后它那个地址也一并去掉。

改完保存"设置成功"不等于修复完成——已经联网的设备手里还是旧租约。 真正的验收标准是客户端续租后拿到新值： Mac 上 ipconfig set en0 DHCP 续租，再看 DHCP 包里 DNS 变成公共 DNS； Windows 上 ipconfig /renew 之后 nslookup 默认服务器变成新地址、网页恢复。 全部通过，才算修好。

四、设备退役清单，多一条"改 DHCP"

一台机器下线，通常大家记得拆电线、删账号，但网络配置里的痕迹最容易漏： 路由器 DHCP 的 DNS、静态地址绑定、端口转发、hosts 文件、定时任务里指向它的 IP。 这些残留不会立刻报错，会以"偶尔慢""莫名其妙上不了网"的形式，隔几周咬你一次。
