Windows 上彗星不飞
把背景动画从系统设置里拆出来

反馈说 Windows 上彗星停在原地，刷新一次换个位置。 这是「只画了一帧」的典型症状：背景脚本跟着系统的「减少动态效果」走了静态分支。 修法是把动画和系统设置解耦，再给帧循环配一个定时器兜底。

症状很好认：彗星不动，但每次刷新位置都不同。位置随机来自生成时的预热， 不动说明绘制只发生了一次——脚本走了「减少动态效果」的静态分支。 这台 Windows 上的系统动画开关查出来是开着的（SPI_GETCLIENTAREAANIMATION 返回 1），无头 Chrome 报告的 prefers-reduced-motion 也是 false， 所以确切触发条件没有复现成功；但结论并不依赖它——背景动画本来就不该押在这个媒体查询上。

三处改动

第一，不再读取 prefers-reduced-motion，动画常开。站点在「减少动态效果」 下原本会自动降级成静态一帧，这个设计这次被明确放弃：读者要的是会飞的彗星， 而不是一张星空海报。

第二，加载完成先同步画一帧，再启动 requestAnimationFrame 循环。 即使浏览器对 rAF 做了节流或暂停，页面至少不是一块空画布，刷新前后的观感也稳定。

第三，加一个看门狗：如果 250 毫秒内没有任何新帧，setInterval 每 60 毫秒接管推进与重绘，rAF 恢复后自动让位。标签页切走时照旧暂停， 切回来时恢复。截图验收的静态帧没有消失，只是入口换成了 URL 参数 ?static=1。

在出问题的机器上验收

截了一张静态图并不能证明「彗星在飞」。这次用 Chrome DevTools 协议直接采样： 在 Windows 上开一个无头 Chrome，连上调试端口，隔 1.2 秒两次读取 canvas.toDataURL() 的摘要，两次不同才算动起来。 结果第一次采样 100362 字节、第二次 103098 字节，判定 ANIMATING， 同一台机器报告的 prefers-reduced-motion 为 false。

同一套采样在 Mac 上复跑，结论一致。命令行截图在虚拟时间下抓不到动画帧， 这个是截图工具的限制，不是页面的问题——动画的验收要落到「两次采样是否一致」上。

留给以后的规则： 背景装饰性动画默认常开，降级只能是可选项，不能是隐性开关； 循环启动前先画一帧；rAF 要有兜底计时器；验收动画用 CDP 采样，不用静态截图。
